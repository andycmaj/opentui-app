## Usage

```sh
tilt-tui up                         # start `tilt up` and open the TUI
tilt-tui up -f deploy/Tiltfile api web   # args after `up` go to `tilt up` as-is
tilt-tui                            # attach to a running tilt on port 10350
TILT_PORT=10351 tilt-tui            # attach to one on another port
tilt-tui logs api -f                # follow one resource's logs, no UI
```

- **`tilt-tui up`** runs `tilt up` as a child process and passes every
  argument through. It won't start over a tilt (or anything else) already on
  that port, shows tilt's error if tilt fails to start, and stops tilt when
  you quit.
- **`tilt-tui`** attaches to a tilt you started; quitting leaves it running.
- **`tilt-tui logs [resource] [-f]`** prints logs to stdout for `grep` or a
  file.

## Features

- **Resource tree** of everything Tilt manages, grouped by Tiltfile label like
  the Tilt web UI, with runtime and build status, build times, and which
  resource a waiting one is blocked on. `e` / `c` expand or collapse every
  group, `d` shows or hides disabled resources, and `ctrl+e` hides the tree.
- **Status filter**: `f` cycles all, healthy, unhealthy, building and pending;
  `esc` resets it.
- **Live logs** for the selected resource: `s` autoscroll, `t` timestamps.
- **Log search**: `/` keeps only matching lines, by plain text or
  `/regex/`, with a match count.
- **Resource picker**: `space` fuzzy-finds any resource and jumps to its logs.
- **Actions**: `r` triggers a rebuild, `ctrl+d` disables or enables a
  resource.
- **Command palette** (`:` or `ctrl+p`): the resource's endpoint links, its
  Tilt buttons and global buttons, and every key's command. Buttons with
  inputs open a form first.
- **Resource info** (`i`): the selected resource's dependency tree, with live
  status. **Watcher info** (`w`): Tilt's file watches, filterable.
- **Self-updating**: checks GitHub for a new release at startup; click the
  footer notice to update with mise.

## Configuration

Settings live in `~/.config/tilt-tui/config.json` and are read at startup.
Every key is optional.

```json
{
  "theme": "tokyo-night",
  "tiltBinaryPath": "/opt/homebrew/bin/tilt",
  "logFilters": {
    "health-checks": ["GET /health", "GET /readiness"],
    "debug-logs": ["^DEBUG:", "\\[debug\\]"]
  }
}
```

- **`theme`**: `default`, `tokyo-night`, `terminal` (your terminal's colors,
  with accents for status) or `mono` (no color). `terminal` and `mono` follow
  a light or dark terminal.
- **`tiltBinaryPath`**: the `tilt` to run, as a path or command name, instead
  of the one on your `PATH`.
- **`logFilters`**: named groups of regular expressions. Matching log lines
  are hidden, and the log header lists the active filters.

Set `GITHUB_TOKEN` or `GH_TOKEN` to avoid GitHub's anonymous rate limit on the
update check.
